Presentation Mode — §31–32
Layout Engine + Deck Chrome

Two layout modes share this design system.

Report Mode (default): body scrolls. Wrap content in .page-content.
Deck Mode: Add class="deck-mode" to <body>. Wrap slides in .deck-wrap. Each panel gets .slide. The JS engine activates navigation — only .slide.active is visible.

Toggle pattern: Report = <body> default with .page-content. Deck = <body class="deck-mode"> with .deck-wrap → .slide panels. Same tokens, palette, and components in both modes. Deck chrome (progress bar, dots, nav buttons) is position:fixed — include it once, outside .deck-wrap.
Deck Mode — HTML Structure
<body class="deck-mode">
  <!-- Progress bar (top edge) -->
  <div class="progress-bar"><div class="progress-fill" id="progress"></div></div>

  <!-- Slides -->
  <div class="deck-wrap">
    <div class="slide active"><div class="slide-inner"> ... </div></div>
    <div class="slide center"><div class="slide-inner"> ... </div></div>
  </div>

  <!-- Navigation chrome -->
  <nav class="deck-nav">
    <button class="deck-btn" id="btn-prev" onclick="goToSlide(current-1)">←</button>
    <span class="deck-counter" id="deck-counter"></span>
    <button class="deck-btn" id="btn-next" onclick="goToSlide(current+1)">→</button>
  </nav>
  <div class="deck-dots" id="deck-dots"></div>

  <!-- JS nav engine (before </body>) -->
  <script> /* goToSlide / goToSection / keyboard / dot wiring */ </script>
</body>

Components — §35
Stat Narrative

Mandatory companion to every chart, KPI tile, or table per CLAUDE.md statistical narration rules. Lead with the user impact sentence, not the raw percentage. Translate ratios to real people where possible.

Conversion
3.75%
badge → mail title
Median days
6.2
badge to title request
96 in 100 lot winners never request their title. Of 68,085 users who saw the You Won badge in the last 30 days, only 2,556 clicked Mail Title — a 3.75% conversion rate. The median winner takes 6.2 days to convert, suggesting the badge creates no urgency at the moment of victory.
Components — §36
Tool Chronicle (MCP Call Log)

Used in methodology slides to make the analysis auditable. Shows which MCP tools were called, what parameters were used, what was returned, and why each call was necessary.

Step 1 build_segment Segment · Build
query: "users who saw the You Won Badge in the last 30 days"
time_range: last_30_days
✓ 69,906 unique users — 320,013 sessions · 316,597 badge events. Segment ID: mLidnrLV0uoc
Why: Establishes the funnel entry universe — every user who received the winning signal. This is the denominator for all conversion math.
Source: Fullstory MCP · app.eu1.fullstory.com
Step 2 build_funnel Funnel · Build
query: "You Won Badge seen → Mail Title button clicked"
in_same_session: false
✓ 68,085 → 2,556 converters (3.75%) · median 6.2 days to convert
Why: Cross-session funnel required — members win a lot, then return days later to request title. Same-session measurement would dramatically undercount conversion.
