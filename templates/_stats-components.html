Statistical Analysis Components

Five statistical visualization components for deep quantitative analysis. Use them when they add clarity that operational charts don't provide. The routing harness below governs which component fits which question.

Rule: Every statistical component must include a .stat-narrative block — a plain-English explanation of what the chart shows and why it matters to the user's question. A chart without a narrative block is incomplete and must not be rendered.
Before You Build Anything
Agent Routing Harness
Work through these gates before choosing a statistical component. Operational charts are faster to read and require no statistical literacy — use them when they're sufficient.
Gate 1 — Has the operational visual already answered the question?
If a trend chart, funnel, top-N bar, segment comparison, gauge, waterfall, histogram, timeline, heat grid, or Sankey can answer the user's question — use that. Operational charts are faster to read, require no statistical literacy, and cover the vast majority of Fullstory Analytics MCP use cases.
Stop — use an operational chart
"Show me rage clicks over time" → trend chart.
"Which page has the most errors?" → top-N bars.
"How does my funnel look?" → funnel waterfall or vertical bar chart.
"Compare mobile vs desktop conversion" → segment comparison bars.
Gate 2 — Would a statistical layer add clarity the operational chart doesn't?
Ask: does the data contain something an operational chart leaves ambiguous? A spike that may or may not be anomalous. A correlation worth quantifying. Outliers that change the interpretation. A distribution whose shape matters. If yes — add the statistical layer. If the operational chart already answers the question clearly, stop here.
Stop — operational chart is sufficient
The data is clear without statistical analysis. Adding a stat chart would be complexity without clarity.
Proceed — statistical layer adds genuine clarity
Use Gate 3 to pick the right component. Mandatory: follow with .stat-narrative in plain English.
Gate 3 — Problem type → statistical component
Match the question to the right chart. Use every component whose statistical layer genuinely clarifies something the operational chart leaves ambiguous.
User's question Statistical component
"Is there a relationship between X and Y?", "Does Y predict X?", "What's the trend line?" Regression Line + R²
"Is this within normal range?", "Is this a real spike or noise?", "SPC / control limits" Control Chart (mean ± σ)
"Show me the spread / distribution", "What's typical?", "Are there outliers in the data?" Box-and-Whisker Plot
"Which values are statistical outliers?", "Flag anomalies", "Show me what's abnormal" Z-Score Anomaly Chart
"Is this normally distributed?", "Expected vs actual distribution", "Bell curve" Normal Distribution Curve
Mandatory: Every statistical component must be followed immediately by a .stat-narrative callout block — a visually distinct section in the deliverable that a non-statistician can find and read. It must cover two things:

1. Reason for inclusion — why statistical analysis was applied here; what question it answers that the operational chart alone could not.
2. Findings in plain English — what the statistical calculations actually show; the results explained for someone with no statistics background.
Statistical Component 1 of 5
Regression Line + R²
OLS linear regression drawn over a scatter of data points. The line shows the best-fit linear relationship; R² (coefficient of determination) quantifies how much of the variance in Y is explained by X. Computed in-page with vanilla JS — no external libraries.
Use when: "Is there a relationship between X and Y?" or "Does [metric A] predict [metric B]?"
Component
Regression Line + R²
.regression-chart → svg + .regression-legend → .r2-badge
Rage click rate (X) vs. conversion rate (Y) across 20 pages — is rage clicking predictive of lost conversions?
What this means
R² = 0.84 means that 84% of the variation in conversion rate across pages is explained by the rage click rate alone — a very strong linear relationship. The negative slope confirms that as rage clicking increases, conversion consistently falls. Pages with rage click rates above 10% (orange and red dots) are losing conversions at a rate far above the average. Prioritize fixing friction on those pages first — a 5-point reduction in rage click rate on the top offender is predicted to recover roughly 12–15pp of conversion.
// OLS linear regression — computed in-page (no libraries) // points = [{x, y}] where x = rage_click_rate, y = conversion_rate function olsRegression(points) { const n = points.length; const sumX = points.reduce((a, p) => a + p.x, 0); const sumY = points.reduce((a, p) => a + p.y, 0); const sumXY = points.reduce((a, p) => a + p.x * p.y, 0); const sumX2 = points.reduce((a, p) => a + p.x * p.x, 0); const slope = (n * sumXY - sumX * sumY) / (n * sumX2 - sumX * sumX); const intercept = (sumY - slope * sumX) / n; const meanY = sumY / n; const ssTot = points.reduce((a, p) => a + (p.y - meanY) ** 2, 0); const ssRes = points.reduce((a, p) => a + (p.y - (slope * p.x + intercept)) ** 2, 0); const r2 = 1 - ssRes / ssTot; return { slope, intercept, r2 }; } // SVG rendering // x_px = X_MIN_PX + (x_val / x_max) * X_RANGE_PX // y_px = Y_MAX_PX - (y_val / y_max) * Y_RANGE_PX (y inverted) // Regression line: compute y at x_min and x_max → two endpoints <!-- MANDATORY: always follow with stat-narrative --> <div class="stat-narrative"> <div class="stat-narrative-header">What this means</div> <div class="stat-narrative-text"> [R² interpretation + slope direction + actionable implication] </div> </div>
Statistical Component 2 of 5
Control Chart (Mean ± σ Bands)
Statistical process control (SPC) chart. A time series trend line with a mean centerline, ±1σ warning bands, and ±2σ control limit bands. Points outside the ±2σ bands are flagged as statistically out-of-control. Computed from the trend series itself.
Use when: "Is this spike within normal variation?" or "Is this process stable?" or "Was this change statistically meaningful?"
Component
Control Chart
.control-chart → svg (bands + trend + outlier dots)
Daily error rate over 30 days — which spikes are signal vs. noise?
What this means
The red dots on June 18–19 are outside the ±2σ control limits — these spikes are statistically out-of-control, meaning they are unlikely to be random variation. The process was stable for the first 17 days (all points within ±2σ). The Jun 18 spike is almost certainly a real event, not noise. Look for a deploy, config change, or traffic pattern shift on that date. Action: investigate what changed on Jun 18 — this is a confirmed signal, not background variation.
// Compute mean and σ from the trend data_points array // values = trend.data_points.map(p => p.value) const mean = values.reduce((a, v) => a + v, 0) / values.length; const sigma = Math.sqrt( values.reduce((a, v) => a + (v - mean) ** 2, 0) / values.length ); const ucl2 = mean + 2 * sigma; // upper control limit const lcl2 = mean - 2 * sigma; // lower control limit const uwl = mean + sigma; // upper warning line const lwl = mean - sigma; // lower warning line // SVG layout — same coordinate system as Full Trend Chart // y_for_mean = 100 - ((mean - y_min) / y_range) * 90 // Band rects: y=y_for_ucl2, height=y_for_lcl2 - y_for_ucl2 // Flag as out-of-control: point.value > ucl2 || point.value < lcl2 <!-- MANDATORY: always follow with stat-narrative --> <div class="stat-narrative"> <div class="stat-narrative-header">What this means</div> <div class="stat-narrative-text"> [How many points are out-of-control, which dates, whether the process stabilized, what to investigate] </div> </div>
Statistical Component 3 of 5
Box-and-Whisker Plot
Displays the five-number summary: minimum (excluding outliers), Q1, median, Q3, maximum (excluding outliers), with individual outlier dots beyond 1.5×IQR. Shows distribution shape, spread, and outliers in a single compact visual. Compare multiple cohorts side-by-side when needed.
Use when: "Show me the spread", "What's typical vs. extreme?", "Are there outliers in session duration / load time / event count?"
Component
Box-and-Whisker Plot
.boxplot-wrap → svg (whiskers + box + median + outlier dots)
Session duration distribution for completers vs. abandoners — are they fundamentally different populations?
What this means
Completers and abandoners have fundamentally different session duration distributions. Completers have a median of 7.2 minutes and a wide spread (Q1–Q3: ~4.5–9m) — they engage deeply and variably. Abandoners are tightly clustered at a median of 2.8 minutes — they leave quickly and consistently, suggesting they hit friction early rather than deliberating. The outliers in the abandoner group (above 8m) are worth investigating: a session that long but still abandoned may indicate form errors or payment failures, not simple disinterest.
// Five-number summary — computed from a sorted array of values function boxStats(values) { const sorted = [...values].sort((a, b) => a - b); const n = sorted.length; const q1 = sorted[Math.floor(n * 0.25)]; const med = sorted[Math.floor(n * 0.5)]; const q3 = sorted[Math.floor(n * 0.75)]; const iqr = q3 - q1; const lo = sorted.find(v => v >= q1 - 1.5 * iqr); const hi = [...sorted].reverse().find(v => v <= q3 + 1.5 * iqr); const outliers = sorted.filter(v => v < lo || v > hi); return { q1, med, q3, lo, hi, outliers }; } // SVG: convert stat values to px using same y formula // Box: rect from y(q3) to y(q1) // Median: horizontal line at y(med) // Whiskers: lines from box edge to y(lo) and y(hi) // Outlier dots: circles at y(outlier_value) <!-- MANDATORY: always follow with stat-narrative --> <div class="stat-narrative"> <div class="stat-narrative-header">What this means</div> <div class="stat-narrative-text"> [Median comparison, spread interpretation, outlier explanation] </div> </div>
Statistical Component 4 of 5
Z-Score Anomaly Chart
Transforms a trend series into standard deviations from the mean. Z-score = (value − mean) / σ. Points at |Z| > 2 are flagged as statistical anomalies. This normalizes different-scale metrics onto the same axis for comparison, or clarifies whether a spike is truly unusual relative to recent history.
Use when: "Which values are actual outliers?", "Is this anomalous?", "Flag the abnormal data points."
Component
Z-Score Anomaly Chart
.zscore-chart → svg (zero line + ±2σ bands + z-series + anomaly dots)
30-day error rate trend — are the June 18 and June 24 spikes statistically anomalous or just high-noise days?
What this means
The June 18 spike (Z = +3.2σ) is a confirmed statistical anomaly — it is more than 3 standard deviations above the monthly mean, which occurs less than 0.3% of the time by chance alone. This is not noise; something real happened. The June 24 spike (Z ≈ +2.0σ) sits right at the control limit — borderline anomalous. Worth monitoring but not yet a confirmed incident. All other days are within ±1σ and are consistent with normal process variation. Action: root-cause Jun 18 as a priority. Jun 24 should be watched over the next 2–3 days to see if it normalizes.
// Transform trend values to z-scores const values = trend.data_points.map(p => p.value); const mean = values.reduce((a, v) => a + v, 0) / values.length; const sigma = Math.sqrt( values.reduce((a, v) => a + (v - mean) ** 2, 0) / values.length ); const zScores = values.map(v => (v - mean) / sigma); // SVG layout // y center = 100 (z=0 → mean line) // y = 100 - z * 25 (each σ = 25px of chart height) // Flag |z| > 2 → anomaly dot (red/orange) // Band rect: y=10..50 (z=+3..+2) and y=150..190 (z=-2..-3) <!-- MANDATORY: always follow with stat-narrative --> <div class="stat-narrative"> <div class="stat-narrative-header">What this means</div> <div class="stat-narrative-text"> [Which points exceed 2σ, confidence that anomalies are real, dates to investigate, borderline cases] </div> </div>
Statistical Component 5 of 5
Normal Distribution Curve
A Gaussian bell curve overlaid on a histogram of observed values. Used to visualize whether a dataset is normally distributed, or to compare expected distribution (the curve) vs. actual observations (the bars). The curve is computed from the empirical mean and σ of the data.
Use when: "Is this normally distributed?", "Compare expected vs. actual distribution", "Show me the bell curve for this metric."
Component
Normal Distribution Curve
.normal-dist → svg (histogram bars + Gaussian polyline + μ line + σ regions)
Session event count distribution — does user behavior follow a normal pattern, or is it skewed toward power users?
What this means
The observed event count distribution (bars) closely follows the expected normal distribution (purple curve), which means user behavior on this metric is approximately normally distributed. This validates that averages and standard deviations are meaningful summary statistics for this dataset — the mean is not being distorted by extreme skew. However, note that the bars are slightly right-skewed — there is a small population of power users with very high event counts that pull the tail longer than expected. This is common in session analytics. The practical takeaway: segment analyses using mean session depth are reliable for 90%+ of users, but the top 5–8% of power users may need separate treatment.
